# 동행이 — 노인 돌봄 에이전트

카메라와 목소리로 어르신 곁을 지키는 에이전트. 낙상·복약 같은 상황을 **카메라가
스스로 알아채고 AI가 먼저 말을 건다**는 것이 핵심이고, 무엇을 지켜보고 어떻게
반응할지는 보호자가 관리 화면에서 정한다.

세 쪽이 하나의 서버를 공유한다.

```
  어르신 iPhone 앱              보호자 웹 콘솔
  (카메라·음성 대화)             (설정 · 배포 · 실시간 관전)
        │                              │
        │ wss /ws/unified?token=…      │ wss /ws/monitor?token=…
        │ (16k PCM · 5fps JPEG)        │ (읽기 전용)
        ▼                              ▼
  ┌──────────────────────────────────────────────┐
  │              에이전트 서버 (FastAPI)           │
  │  Gemini Live · 감지 그래프 · SQLite 설정 저장소  │
  └──────────────────────────────────────────────┘
```

- **어르신**은 코드 6자만 넣는다. 이메일·비밀번호를 치게 하지 않는다.
- **보호자**는 계정으로 들어와 자기 어르신의 설정만 본다.
- 둘은 `agent_id`로 묶인다. 계정 하나에 에이전트 하나, 에이전트 하나에 코드 하나.

---

## 1. 감지 — 카메라가 먼저 알아챈다

`detection_graph.py`(LangGraph)가 **프레임 → Detect → Decide → Nudge** 3단계를
정의하고, 시나리오마다 이 그래프 하나를 프롬프트·타겟이벤트·쿨다운·확신도 하한만
바꿔서 재사용한다. 감지 모델은 OpenRouter 경유 `meta-llama/llama-4-scout`
(Groq 우선 라우팅, 혼잡 시 자동 대체).

시나리오는 코드가 아니라 **DB에 있다.** 배포하면 `agent/scenarios/<agent_id>/*.yaml`로
내보내지고, 세션이 시작될 때 읽힌다.

## 2. 프로액티브 발화 — 이 프로젝트의 핵심 트릭

Gemini Live는 반응형이라 스스로 먼저 말하지 않는다. 감지가 확정되면
`send_client_content(turn_complete=True)`로 **턴을 강제로 발생**시켜, 그때까지
쌓인 영상·음성 맥락을 근거로 자연스럽게 먼저 말하게 만든다 (`gemini_live.py`).

## 3. 판단은 프롬프트에 위임한다

"낙상이면 괜찮은지 묻고 필요하면 연락", "복약이 확인되면 칭찬" 같은 판단은
코드가 아니라 시스템 프롬프트가 한다. `agent/persona.py`가 연결마다
**기본 페르소나 + 어르신 프로필 + 시나리오별 지침 + 사용 가능한 도구**를 조립한다.
지침에 행동(도구)이 붙어 있으면 그 자리에서 도구 호출을 지시하는 문장으로 렌더링된다.

## 4. 설정은 버전으로 관리한다

`admin_store.py` (SQLite, `data/console.db`)

- **draft**: 편집 중인 설정 (에이전트당 1행)
- **config_versions**: 배포된 스냅샷. 불변 — 롤백도 "예전 스냅샷을 새 버전으로 다시 배포"
- **profiles**: 어르신 프로필. 배포를 거치지 않는다 — 사실을 고치는 데 승인이 필요할 이유가 없다
- **events**: 활동 로그 (append only)

진실의 원천은 DB이고, 런타임이 읽는 yaml은 배포 시 내보내는 산출물이다.

> **반영 시점**: Gemini Live는 세션 시작 때만 시스템 프롬프트를 고정할 수 있다.
> 지침을 고쳐 배포하면 **다음 "대화 시작"부터** 적용된다 (콘솔이 변경 항목에
> `tier: next`로 표시한다). 감지 기준 같은 값은 `tier: instant`.

## 인증 — 보호자와 어르신을 따로 본다

| | 보호자 | 어르신 폰 |
|---|---|---|
| 수단 | 이메일 + 비밀번호 | **6자 코드** |
| 토큰 | `<user_id>.<서명>` | `d<agent_id>.<서명>` |
| 서명 대상 | `"<id>"` | `"device:<id>"` |
| 권한 | 설정 조회·수정·배포·관전 | 대화 세션만 |

서명 대상 문자열을 다르게 둔 이유는, 같은 형식이면 폰 토큰으로 보호자 API를
부르거나 그 반대가 가능해지기 때문이다. 폰은 대화만 할 수 있고 설정은 못 바꾼다.

**코드는 가입 시 에이전트마다 발급**되고 `agents.pair_code`에 저장된다.
알파벳에서 `I/1/L`, `O/0`을 뺐다 — 보호자가 화면으로 읽고 폰에 옮겨 적는 값이라
헷갈리는 글자가 그대로 오독이 된다.

```
POST /api/pair  {"code": "2VD58V"}
→ {"token": "d2.…", "agent_id": 2, "elder_name": "…"}
```

이후 앱은 `/ws/unified?token=…`으로 붙고, 서버가 토큰에서 `agent_id`를 꺼낸다.
서명 없는 `?agent=N`도 아직 받지만 경고 로그를 남긴다.

## iOS 앱 ([`ios/`](ios/))

의존성 없는 SwiftUI 앱. 브라우저 대신 앱이 같은 WebSocket 프로토콜을 말한다.

| 방향 | 프레임 | 내용 |
|---|---|---|
| 앱 → 서버 | binary | 16kHz mono PCM16 (마이크) |
| 앱 → 서버 | text | `{"type":"image","data":"<base64 jpeg>"}` — 초당 5장 |
| 서버 → 앱 | binary | 24kHz mono PCM16 (AI 음성) |
| 서버 → 앱 | text | `gemini` / `user` / `detect_result` / `alert` / `system_nudge` / `memory_update` … |

브라우저 대비 이점:

- **하드웨어 에코 캔슬(VPIO)** — 스피커로 나간 목소리를 마이크가 되받아 모델이
  제 말에 반응하는 문제가 사라진다. AEC를 켠 채로 엔진이 안 뜨면 자동으로 끄고
  재시도한다(조용히 실패하지 않게).
- **지터 버퍼** — 220ms 모은 뒤 80ms 단위로 이어 붙인다. 도착한 조각을 그대로
  재생하면 네트워크 지터가 그대로 소리 구멍이 된다.
- 화면이 꺼져도 대화 유지 (Background Audio), 화면 자동 잠금 해제

화면은 둘이다. **코드 입력** 화면과 **대화** 화면. 대화 화면의 상태 표시줄을
길게 누르면 연결 설정(서버 주소 변경·코드 재입력)이 열린다 — 어르신이 실수로
열 일이 없게 길게 눌러야 한다.

빌드는 [`ios/SETUP.md`](ios/SETUP.md) 참고. Swift 원천은 `ios/Sources/` **한 곳**이고
`./install.sh`가 Xcode 앱 타겟으로 복사한다 (두 벌을 커밋하면 반드시 어긋난다).

## 보호자 콘솔 ([`../admin-console/frontend`](../admin-console/frontend))

React + Vite. 시나리오·행동·연락처 편집, 버전 배포/롤백, 어르신 온보딩 인터뷰,
그리고 **모니터링**.

모니터링 화면(`/ws/monitor`)은 **읽기 전용**이다 — 콘솔을 열어둔 것 때문에
어르신과의 대화가 달라지면 안 된다. 세션 웹소켓을 `MirroredSocket`으로 감싸
지나가는 모든 이벤트를 관전 채널에 복사한다(송신부마다 한 줄씩 넣으면 새
이벤트를 추가할 때 빠뜨린다).

- 어르신 이름과 연결 시각을 제목에 둔다 — 계정을 여러 개 쓰는 보호자가 엉뚱한
  어르신을 보면서 괜찮다고 판단하는 것을 막는다
- 기기가 아직 안 붙었으면 **연결 코드 패널**을 띄운다 (복사·재발급)
- 영상은 **새 장면이 생겼을 때만** 보낸다. 고정 간격으로 퍼내면 기기가 더 자주
  보내도 화면이 그만큼 끊기고, 기기가 멈춰 있으면 같은 장면을 반복해 싣는다
- 모델 발화는 토큰 단위로 도착하므로 같은 화자의 연속 발화는 한 줄로 합친다

## 실행

```bash
# 1) 에이전트 서버
python -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env          # GEMINI_API_KEY, OPEN_ROUTER_KEY
PORT=8004 .venv/bin/python main.py

# 2) 보호자 콘솔 (개발 중)
cd ../admin-console/frontend && npm install && npm run dev
```

콘솔 dev 서버는 `/api`·`/ws`를 **8004**로 프록시한다(`vite.config.js`). 서버 기본
포트는 8003이므로 콘솔과 함께 쓸 때는 `PORT=8004`로 띄운다.

배포본에서는 콘솔을 빌드해 `drone-agent-app/console/`에 두면 서버가 `/`에서
직접 서빙한다. 그 디렉터리가 없으면 조용히 건너뛰고 옛 데모 페이지를 보여준다.

**폰에서 맥북 서버로 붙기**: 앱의 연결 설정에 `http://<맥 IP>:8004`를 넣는다.
`Info.plist`의 `NSAllowsLocalNetworking`이 사설 대역에만 평문을 허용한다
(인터넷 구간은 TLS 강제 유지).

### 주요 엔드포인트

| 경로 | 용도 |
|---|---|
| `WS /ws/unified?token=` | 어르신 기기 ↔ 에이전트 (음성·영상·이벤트) |
| `WS /ws/monitor?token=` | 보호자 관전 (읽기 전용) |
| `POST /api/pair` | 코드 → 기기 토큰 |
| `POST /api/admin/signup` · `/login` · `/me` | 보호자 계정 |
| `GET /api/admin/pair-code` · `POST …/regenerate` | 연결 코드 조회·재발급 |
| `GET/PUT /api/admin/draft` · `POST /publish` · `/rollback/{v}` | 설정 버전 관리 |
| `GET /api/admin/events` | 활동 로그 |
| `POST /api/remind-medication` | 데모용 복약 넛지 주입 |

## 알려진 한계

- **세션 핸들이 전역 하나**다 (`_active_unified_session`). 어르신 두 명이 동시에
  접속하면 나중 사람이 앞사람을 밀어낸다. `/api/remind-medication`도 "지금 붙어
  있는 그 한 명"에게만 간다. 멀티 테넌트를 제대로 하려면 `agent_id → 세션` 맵이
  필요하다.
- **배포가 실행 중인 세션에 닿지 않는다.** `_apply_live_to_runtime()`이 로그만
  찍고, 세션을 끊어 재연결을 유도하는 `/api/scenarios/reload`는 배포 경로에서
  호출되지 않는다. 앱에 자동 재연결이 없어 어르신이 버튼을 눌러야 한다.
- **토큰에 만료가 없다** (PoC). 서명은 있으므로 위조는 막히지만 회수는 안 된다.
- 앱에 자동 재연결이 없다. 끊기면 "대화 시작"을 다시 눌러야 한다.
- 무료 Apple 계정으로 서명한 앱은 7일 뒤 만료된다.
